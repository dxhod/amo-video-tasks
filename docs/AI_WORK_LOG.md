# Історія роботи з AI

Це індекс рішень і виправлень. [Витяг з реальної сесії](AI_SESSION_EXCERPT.md) містить видимі повідомлення користувача й асистента; системні інструкції та виводи інструментів виключено.

| Момент | Рішення / знайдена помилка | Виправлення та свідчення |
|---|---|---|
| Планування | Вибрано web + worker, Supabase Queues, одну доріжку й незмінні після Render версії | Підтверджено користувачем у сесії |
| Схема | Старий рендер не повинен змінювати актуальну картку | Перевірка current_version_id і статусу в worker_complete; інтеграційний сценарій v1/v2 |
| Перша перевірка | Помилка синтаксису SSR-клієнта та явних Node-типів TypeScript | Виправлено перед успішною перевіркою типів |
| Складання worker | CLI tsup не приймав --no-external у використаній формі | Перенесено noExternal до tsup.config.ts; worker збирається |
| Перевірка UX | Перемикання версії могло випередити автозбереження | Спільний flush перед копіюванням та вибором версії |
| Таймлайн | Мінімальна CSS-ширина і gap спотворювали шкалу коротких фрагментів | Ширина відповідає кількості кадрів, без проміжків |
| Локальні перевірки | Docker спочатку не працював | Запущено Docker Desktop; образи Supabase завантажуються локально |
| Supabase integration | Кваліфікація локальної SQL-змінної як amo_command.key не працювала | Змінну перейменовано на idempotency_key; усі 5 інтеграційних сценаріїв пройшли |
| Auth E2E | Next.js внутрішньо використовував localhost для запитів до 127.0.0.1 | Єдиний requestOrigin з обмеженим локальним host; підтвердження email та reset password пройшли |
| Командний E2E | Завершення додавання учасника закривало вже відкриту форму задачі | Перемикання форм недоступне під час збереження |
| Плеєр | loadedmetadata скидав playhead на початок | Відновлюється поточний кадр; split і рендер v2 перевірені |
| TUS E2E | Потрібен доказ продовження частково переданого файлу | Перервано PATCH після 6 MiB, reload, продовження з upload-offset; тест пройшов |
| Docker worker | Slim-образ не мав CA для першого HTTPS-запиту APT | Початкове отримання пакетів через HTTP із перевіркою підписів Debian; повторна збірка |
| Docker web | Внутрішній Supabase URL відрізняється від браузерного | SSR використовує внутрішнє з’єднання зі сталим namespace cookie; посилання на MP4 повертаються з публічним URL |

Фактичний стан перевірок — у `docs/TEST_RESULTS.md`. Зовнішній deploy не представляється як виконаний.
# Зміна моделі версій та видалення проєктів, 2026-09-07

Після підтвердження користувача замінено постійне блокування версії після Render на блокування за статусом задачі та активним job. Для збереження історії додано `version_revision` до jobs/renders і унікальність на пару версія/ревізія. Перевірка актуальності MP4 виконується у БД перед review. У першому інтеграційному прогоні знайдено конфлікт SQL-аліаса `v` зі змінною функції; виправлено, повторний прогін 9/9 успішний. М’яке видалення проєкту зберігає незалежні маркери видалення задач. Docker E2E підтвердив повторний монтаж v1, збереження старого MP4, v2, review/done та відновлення проєкту.
